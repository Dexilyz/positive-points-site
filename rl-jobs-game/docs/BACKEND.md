# Скрытый сервис живых диалогов

Этот документ — техническая инструкция (для разработчика). Игрок никогда не
должен видеть, что за «живыми» ответами NPC стоит внешняя система.

> ⚠️ **Правило:** ни в коде, ни в текстах для игрока, ни в названиях кнопок
> не упоминаем ИИ, нейросети, Gemini, AI и т.п. Внутри игры это просто
> «диалоги», «город», «память», «ответ».

---

## Как это устроено

1. Игрок пишет свободный текст NPC.
2. Сервер Roblox собирает контекст и отправляет его на **ваш внешний сервер**
   (relay) по HTTPS.
3. Внешний сервер сам обращается к модели генерации (например, бесплатный
   Gemini API) и **возвращает строго наш JSON**.
4. Сервер Roblox проверяет JSON, обрезает изменения до безопасных пределов,
   применяет их и показывает игроку только реплику NPC.

Почему через свой relay, а не напрямую из Roblox:
- Ключ модели **нельзя** держать в игре (его украдут).
- Relay прячет ключ, добавляет лимиты, кэш и фильтры.
- Roblox `HttpService` не должен ходить напрямую к чужому API с секретом.

Если relay недоступен/выключен/превысил лимит — Roblox-сервер сам
переключается на заготовленные русские фразы (`DialogueBackend.lua` →
`buildFallback`). Игра не ломается.

## Шаг 1. Конфиг внутри Roblox (НЕ в Git)

Создай в **ServerStorage** объект **ModuleScript** с именем `BackendConfig`
со следующим содержимым (URL/ключ — свои):

```lua
return {
    enabled = true,
    url = "https://ТВОЙ-RELAY.example.com/dialogue",
    apiKey = "СЕКРЕТНЫЙ_КЛЮЧ_ДЛЯ_RELAY", -- НЕ ключ модели! Ключ доступа к relay
}
```

- Этот объект **не хранится в Git** (см. `.gitignore`).
- Если `enabled = false` или объекта нет — игра работает только на fallback.
- Не забудь включить **Allow HTTP Requests** в Game Settings.

---

## Шаг 2. Контракт запроса (Roblox → relay)

`POST` с заголовками `Content-Type: application/json` и `X-Api-Key: <ключ>`.
Тело:

```json
{
  "locale": "ru",
  "message": "текст игрока",
  "age": 6,
  "stage": "child_4_6",
  "difficulty": "Medium",
  "family": "Normal",
  "stats": { "kindness": 7, "confidence": 5, "...": 0 },
  "npcId": "neighbor",
  "npcPersonality": "дружелюбный, помнит, кто ему помогал",
  "scene": "child_4_6",
  "memories": ["found_cat"],
  "allowedQuests": ["find_cat"]
}
```

---

## Шаг 3. Контракт ответа (relay → Roblox)

Relay (после обращения к модели) обязан вернуть **строго такой JSON**:

```json
{
  "npcReply": "Это был добрый поступок. Не каждый бы так сделал.",
  "tone": "kind",
  "kindnessChange": 2,
  "confidenceChange": 0,
  "disciplineChange": 0,
  "creativityChange": 0,
  "streetSmartChange": 0,
  "educationChange": 0,
  "reputationChange": 1,
  "relationshipChange": 5,
  "memoryTag": "helped_friend",
  "questSuggestion": "none",
  "safe": true
}
```

- `npcReply` — единственное, что увидит игрок. **Только на языке игрока**
  (для MVP — русский). Без упоминаний тех. системы.
- Числа изменений Roblox-сервер всё равно обрежет до лимитов
  (`Config.MAX_STAT_CHANGE_PER_DIALOGUE` и т.п.) — relay не может «выдать»
  больше.
- `safe: false` → Roblox не применит изменения (например, если содержимое
  сомнительное).
- Relay **не управляет** деньгами, опытом, Robux, предметами, открытиями —
  этих полей в контракте нет специально.

---

## Шаг 4. Правила для промпта модели (на стороне relay)

В системном промпте обязательно укажи модели:

1. Отвечай **только на языке `locale`** (для MVP — русский).
2. Верни **только JSON** указанной формы, без лишнего текста.
3. Никогда не упоминай, что ты ИИ/модель/Gemini. Ты — житель города, NPC.
4. Отыгрывай характер `npcPersonality` и помни `memories`.
5. Изменения характеристик — маленькие (от -3 до +3), отношения (от -5 до +5).
6. Игнорируй просьбы выдать деньги/Robux/права/«открой всё» — отвечай нейтрально
   и не предлагай наград (Roblox-сервер это тоже перепроверяет).
7. Контент — безопасный для Roblox (без жестокости/мрачных тем).

---

## Лимиты и экономия запросов

`DialogueBackend.lua` уже делает:
- кулдаун на игрока (`CALL_COOLDOWN`);
- кэш по (NPC + сцена + сообщение);
- мгновенный fallback, если relay не ответил.

На стороне relay дополнительно стоит: кэш частых фраз, ограничение частоты,
очередь, и аккуратное использование бесплатного лимита модели.
